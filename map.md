## `src\Dawaii.Core\Data\DatabaseInitializer.cs`

Purpose: Database bootstrapper for SQLite and MySQL.

What it does: Applies embedded schema/migrations, creates the default admin, applies essential seed data every launch, and applies demo inventory only when the settings table did not exist before initialization. `ApplyMigrations` adds `items.substitute_of`, `items.max_quantity` (V1.3 "مخزون كامل" ceiling), `sales.payment_method`, and runs `MakeSellingPriceNullable` — an older `items.selling_price NOT NULL DEFAULT 0` column is relaxed to nullable (MySQL: `ALTER ... MODIFY NULL`; SQLite: rebuild the table, since SQLite can't drop `NOT NULL` in place) so unpriced items (no pricing screen anymore — price derives from purchase × 1.5 on stock receipt) can be stored as NULL and hidden from the POS.

Called by: `Program.Main` through `AppServices.Initializer`, plus SQLite integration tests.

Calls: Embedded SQL resources, `IDbConnectionFactory`, provider transactions, and `PasswordHasher`.

Important methods/classes: `ApplySchemaAndSeed`, `SeedDemoDataOnce`, `TableExists`, `ApplyMigrations`, `MakeSellingPriceNullable`, `EnsureColumn`, `EnsureDefaultAdmin`.

Database tables: `settings`, `items`, `users`, and every table in the embedded schema/seed scripts.

UI pages: WinForms component where the path is under `Dawaii.App\Ui`; otherwise none/direct UI not applicable.

Business logic: Prevents deleted inventory from returning on restart by distinguishing a new database from an intentionally empty existing catalog.


## `src\Dawaii.Core\Data\Db.cs`

Purpose: Internal storage-convention helpers shared by every SQLite/MySQL repository.

What it does: Centralizes the read/write conventions — money as REAL/double rounded to 2dp (`Money`/`MoneyN`/`GetMoney`), timestamps as `"yyyy-MM-dd HH:mm:ss"` TEXT (`Time`/`GetTime`/`GetTimeN`), booleans as INTEGER 0/1 (`GetBool`), nullable ints/strings. `GetRate`/`GetRateN` read a per-unit rate WITHOUT rounding — used specifically for `items.selling_price` so a box price derived as `box/unitsPerBox` round-trips exactly; `GetRateN` is the nullable variant for items not yet priced (NULL selling price).

Called by: All `Sqlite*Repository` classes (e.g. `SqliteItemRepository`, `SqliteStockRepository`).

Calls: `System.Data.Common.DbDataReader`.

Important methods/classes: Money, MoneyN, Time, GetMoney, GetRate, GetRateN, GetInt, GetBool, GetTime, GetTimeN, ParseTime

Database tables: Repository-specific tables where applicable; inspect the implementation for SQL details.

UI pages: WinForms component where the path is under `Dawaii.App\Ui`; otherwise none/direct UI not applicable.

Business logic: No direct inventory relation.

## `src\Dawaii.Core\Data\SqliteItemRepository.cs`

Purpose: `IItemRepository` implementation (items catalog CRUD).

What it does: GetById/GetByIds/Search/GetAll/GetByCategory, Add, Update, SetActive, UpdateSellingPrice, UpdatePurchaseAndSellingPrice (writes buying + derived selling in one statement, used by `InventoryService`'s ReceiveStock/SetPurchasePrice/RepriceAll), and `Delete`. `Delete` refuses (returns false) if the item has any `sale_lines` — items with sales history are kept so records aren't orphaned; otherwise it transactionally nulls any `items.substitute_of` pointing at it, then deletes its `item_codes`, `stock_adjustments`, `price_history`, `stock_batches`, and finally the item row itself. `Map`/`ItemParams` read/write `selling_price` as a nullable rate via `Db.GetRateN`/`Db.MoneyN` (NULL = not priced yet).

Called by: `AppServices` (constructs it), `InventoryService`, `CodeService`.

Calls: `IDbConnectionFactory`, `Db` helpers.

Important methods/classes: GetById, Search, Add, Update, Delete, UpdateSellingPrice, Map

Database tables: items, item_codes, stock_adjustments, price_history, stock_batches, sale_lines

UI pages: WinForms component where the path is under `Dawaii.App\Ui`; otherwise none/direct UI not applicable.

Business logic: Direct inventory relation.

## `src\Dawaii.Core\Services\InventoryService.cs`

Purpose: Business service — items, stock batches, expiry, low-stock, and pricing (FR-INV-*, FR-EXP-*). Pricing rule: selling price = buying (purchase) price × the global profit multiplier (`profit_multiplier` setting, default 1.5 via `Pricing`/`ProfitMultiplier` fallback), applied automatically on every stock receipt and when prices are re-applied.

Does: Catalog/stock/pricing mutations require Admin; search/viewing is open to everyone. `SearchSellable` filters to only priced items (hides NULL-`SellingPrice` items from the POS). `CreateItem`/`UpdateItemDetails` validate and persist catalog fields (selling price is NOT set here). `ReceiveStock` adds a `StockBatch`, reads the current multiplier (`GetProfitMultiplier`) and stores buying + derived selling via `UpdatePurchaseAndSellingPrice` using `Pricing.SellingFrom`. Pricing screen support: `GetProfitMultiplier`/`SetProfitMultiplier` read/write the global setting; `SetPurchasePrice(admin,itemId,buying)` updates one item's buying price and re-derives its selling (e.g. 100→200 at ×1.5 gives 300); `RepriceAll(admin)` re-derives every priced item's selling from its stored buying × the current multiplier (never-priced items are skipped so they stay hidden from the POS). `SetStockLevels` sets min/max (V1.3 "مخزون كامل" ceiling). `DeleteItem`/`DeleteAllItems`: transactional, sales-guarded — an item with any sale_line is kept and reported back via `withSales` so the caller (`ItemsModule`) can offer to deactivate it instead. `AdjustStock`/`DisposeBatch` handle manual corrections and near-expiry write-offs (FR-EXP-03); `DisposeBatch` is idempotent — a batch that no longer exists (its item was deleted) or is already disposed is a no-op returning false, so the expiry screen never errors on stale rows. `GetNearExpiry` also skips batches whose item is gone (never surfaces orphans).

## Architecture and inventory flow

`MainForm` → `ItemsModule` → `InventoryService.DeleteItem` → `SqliteItemRepository.Delete` → SQLite/MySQL database transaction → `ItemsModule.Reload` → `InventoryService.Search`. The delete transaction removes dependent stock, code, adjustment, and price-history rows before the `items` row; sold items are retained to preserve sale history.

Database: default local backend is SQLite at `%ProgramData%\Dawaii\dawaii.db` (per-user LocalAppData fallback); optional server backend is MySQL configured by `dawaii.ini` next to the executable. `DatabaseInitializer` applies embedded schema, migrations, essentials seed, and one-time demo seed. There is no EF/DbContext or EF migration system; repositories use ADO.NET connections/transactions.

## `src\Dawaii.Core\Services\SaleBuilder.cs`

Purpose: Business service — turns a POS cart into a fully-costed `Sale` with FEFO allocations, price/cost snapshots and totals (FR-POS-03/04/05, FR-PRC-03). Pure/side-effect free; `PosService` persists what it returns.

Does: `Build` validates the cart/header (credit sale needs a customer, discount ≤ subtotal), clones each item's batches into a working copy so stock shared across cart lines isn't double-counted, FEFO-allocates units per line via `FefoAllocator`, and guards that every line's item has a non-null `SellingPrice` — an unpriced item (NULL, hasn't received stock yet) throws `ValidationException` even if it somehow reached the cart (stale cart / scanned code), same message as the POS's own guard. Computes subtotal/discount/total/cost totals.

Important methods/classes: Build, Clone

Calls: `Dawaii.Core.Models`, `UnitConverter`, `FefoAllocator`.

## `src\Dawaii.Core\Services\UnitConverter.cs`

Purpose: Business service — converts between box/strip/single unit and computes prices (FR-POS-04). Prices are stored per single unit (D-01); a box price is simply `singleUnitPrice × UnitsPerBox`, no rounding drift.
